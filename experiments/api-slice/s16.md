# S16 isolated response-contract experiment

Executed September 26, 2026, against the clone containing the agreed
[baseline](https://github.com/robertguss/Iris/commit/8730e9c9682093246186c86f11e2e7ecdba897ac).
This is engineering verification, not an agent-productivity study or API
migration. Neither existing demo registers this router. No UI was changed.

## Run the experiment

From the repository root, with Rust 1.98.1 and Node 26 available:

```sh
npm --prefix experiments/api-slice/web ci
npm --prefix experiments/api-slice/web run verify:s16
npm --prefix experiments/api-slice/web run probe:s16
cargo test --locked -p iris-api-spike --features dev-identity -p iris-sqlite-spike
cargo clippy --locked -p iris-api-spike --all-targets --features dev-identity -- -D warnings
cargo fmt --all -- --check
npm --prefix experiments/api-slice/web run verify
git diff --check
```

`generate:s16` updates only `contracts/s16.json` and `web/s16/generated.ts`,
then runs the same behavioral/client checks. `export-s16 OUTPUT_FILE` assembles
the real `routes!` router and exports its post-processed document.
`s16::authenticated` assembles that separate router with the existing
session/CSRF middleware; it does not need an interactive documentation server.
The test issuer and disposable databases use existing fixtures. There is no new
demo binary or external service.

## What is shared, and what remains explicit

`server/src/s16/action.rs` owns the command, rejection descriptors, and ordinary
SQLx transaction. `mod.rs` owns exhaustive public projections and the narrow
response bridge. One mapping feeds both rendering and status-grouped OpenAPI
schemas. The 403 response contains a `oneOf` for CSRF refusal and domain
forbidden. The bridge assigns the operation-name pair and checks collection
cardinality, method, inferred handler identity and duplicate public codes.
Request DTOs and referenced success schemas use existing utoipa derives.

The existing `ApiError` renderer adds a nonserialized response-extension marker.
Only the isolated outer boundary consumes it. It preserves cookies and no-store,
retains a locally generated request ID even when inner middleware replaces a
response, and does not classify arbitrary 4xx or unrelated errors. Existing wire
bodies, demos, both previous exporters and their snapshots remain unchanged.

Librarian research confirmed utoipa 6.0.0 / utoipa-axum 0.3.0's mutable
collected operation seam and strum 0.28.0 unit enumeration. Ajv 8.20.0's
`Ajv2020` validates draft-2020-12 schemas; openapi-typescript 7.13.0 generates
static types. Ajv is pinned at a patched release (`npm audit`: zero
vulnerabilities). The client registers the exported components pointer namespace
without treating the entire OpenAPI document as JSON Schema. Strict validation
stays on; no coercion, defaulting, property removal, remote reference fetches or
automatic retries. The tested extension consumer reads recovery capabilities
from the export.

The oracle reviewed acceptance criteria before implementation. Its refinements
led to a `RAISE(FAIL)` control that distinguishes statement effects from
explicit rollback, a real post-commit session-save failure with an
unmodified-session control, and negative middleware/route classifications.

obligation at a time, checks the expected failure, and removes the copy in
`finally`. It never edits this checkout. The hypothetical archived policy
applies to seeded project 41 only in that copy; it is not shipped membership
behavior. The complete temporary rejection passes its independent business
scenario and automatically appears in export without a route or enumeration-list
edit.

## Findings and limits

The narrow bridge works with the pinned ecosystem: it removes separately
authored response tables for this route, preserves same-status alternatives, and
supports runtime validation and useful generated narrowing. No evidence here
justifies a typed registration wrapper. **Route/reply linkage still requires
contract tests**; raw `Response` can bypass the bridge and a different mounted
handler could compile. The negative tests catch the sampled bypasses, not all
possible misassemblies. A larger module still needs an explicit association.

The result distinguishes body stop, finalized rejection and request failure.
**Public 500 is not evidence of non-commit.** The real session test demonstrates
this directly. Client unknown likewise supplies no action-effect conclusion;
later forbidden is a separate attempt, not resolution of the earlier one. No
inspector, read endpoint, replay key, receipt, retry policy or agent mutation
interface has been added. Recovery metadata supplies constraints, not authority.

Failure vocabulary is deliberately small (Busy/Other). Cleanup is
`RollbackAcknowledged` or `Unconfirmed { rollback_error: Option<FailureKind> }`;
None records no observed rollback error, not completed cleanup. Begin/commit
errors stay conservative; no `NotRequired` claim is made. The handler uses a
fresh connection and drops it rather than returning it to a pool. This does not
prove immediate lock release or safe reuse after every driver fault.

Failed-cleanup observations are injected at the finalizer instead of executing a
failing driver rollback. Real rollback I/O failure, dropped futures, lost commit
acknowledgment, process death, network disconnect timing, bounded body reads,
engine portability and all other mutation paths are **not established**. The 44
client cases use real in-process bodies inside synthetic Fetch responses, not a
browser/network reliability test. OIDC fixture discovery/session middleware is
real, but these tests provision trusted sessions directly rather than repeat the
complete login flow. Existing auth tests still cover that flow. Canary tests
cover these public projections, not all nested instrumentation.

Keep wire migration, larger-module registration and production disposal policy
open. This supports S16 alternative A for the bounded experiment, not a released
framework contract or a productivity claim.
